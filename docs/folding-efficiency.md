## 运行

已有 Bun、Git 和项目依赖即可；脚本不安装依赖、不调用推理或计费接口。将工作流分配的 jobtmp 绝对目录作为参数：

```sh
bun scripts/folding-efficiency.ts /home/lightjunction/.claude/jobs/1c0cc0a1/tmp
```

每次运行在该目录下创建独立的 `magpie-folding-efficiency-*` 子目录，不覆盖历史结果。参数必填，没有 `/tmp` 默认输出。脚本从 Git 读取上述提交的所有 `src` 文件作为 baseline，再复制当前工作区中已跟踪及未被忽略的新增 `src/*.ts` 文件作为 current；两个副本各有独立的配置目录、项目配置查找边界和 SQLite 状态目录，复用现有依赖。两个 worker 并行运行，均将 `fetch` 替换为计数并拒绝网络访问的函数。不更改 live 配置或状态。

`result.json` 保存脚本和源码 SHA-256、基线提交、运行时版本、每轮计量、总计、恢复与重放断言结果；`baseline-result.json`、`current-result.json` 保留各自的明细。源码快照和状态库留在同一 jobtmp，便于核对。脚本不生成逐轮完整请求日志，也不写入或覆盖 `docs` 下的历史测量结果。

## 固定条件与口径

使用一个确定性生成的 chat 请求序列，共 12 轮，覆盖八个独立模块的工具证据和助手历史。模块文本分别带有独立编号，没有人为注入重复内容；本组隔离测量折叠表示与 guide 开销，不量化分组或精确重复替换的收益。每轮原文、消息角色和顺序、模型字段、两项工具定义、八次历史工具调用及其 432 字节参数，在 baseline 和 current 中完全一致。消息数从 27 条增加到 49 条，正常历史增长也纳入相同工作量。脚本检查请求原件没有被 hooks 修改，以及工具定义、调用参数、工具返回 ID、消息角色和数量都被保留。

两边使用 `intelligence` 模式及其 `thresholdTokens=64000`、`keepRecentMessages=12`、`headChars=400`。仅统一将 `autoRoles` 设为空，避免不同自动挑选行为污染格式比较；两边都对同样六条、可折叠且已完成的历史应用预先提供的相同摘要，每条依次为 1600、900、63 个字符，在第 1、5、9 轮标记。摘要不由模型生成。实际摘要内容、目标 ID、配置和原始历史哈希在结果中逐项断言相等。

计量对象是 `Buffer.byteLength(JSON.stringify(request))`：包括完整消息、工具定义、参数、折叠表示、JSON 转义、guide 和预算提示。不包括 HTTP 报头、传输封装或供应商内部模板。`bytes/4` 只是估算，逐轮向上取整后求和，既不是 tokenizer 计数，也不是计费 token。未运行 BPE 或任何模型推理。

每个版本另有一次相同的归档发现调用、三批本地 `mark`、五次相同请求的 warm replay 和恢复验证。三批 `mark` 的参数与结果序列化字节分别报告，并断言两边一致。这些本地操作不产生模型请求，未计入 12 轮请求合计；它们在实际部署中若引起额外模型输入、输出或恢复调用，其费用仍需另测。脚本保留各轮本地 hooks 耗时，但两个 worker 并行运行，因此不能将其作为受控的延迟或运行速度对比。

## 恢复与重放验证

baseline 和 current 均通过以下断言：

- 40 条归档原文与固定输入历史逐字核对，再逐页读取；每页返回的 SHA-256 与完整原文哈希相符，所有输入文本均有对应归档。
- 六条折叠历史各有三层，共 18 个层；每层与创建时的出站表示逐字核对并逐页精确恢复，所有 `previousId` 链无环并最终到达 `original`，没有不可达层。
- 每个版本共 282 次本地分页读取；中文、表情符号、引号、反斜杠和换行均被恢复。
- 五次 warm replay 输出严格相等，层数维持 18 → 18，归档文本、标记、折叠表示和层不变。状态库在本次验证结束时均为 1,146,880 字节。
- 两个 worker 的网络调用尝试均为 0；模型请求为 0，计费接口请求为 0。

精确恢复验证的是数据保留能力。它没有测量折叠摘要能否让模型保持相同推理质量，也没有测量用户实际请求的效果或费用。
