# 注释主动折叠协议（0.4.0）

折叠是一项明确的文本替换：Agent 写出开始与结束标记，宿主保存中间的原文，再在后续请求中用可恢复的短引用替换它。何时整理上下文、哪些内容可以收起，由 Agent 判断；模型窗口大小和上下文预算不属于本项目的配置或机制。

## 标记

核心语法只有两行：

```text
@context-fold begin LABEL
@context-fold end LABEL
```

在聊天文本中，建议使用完整 HTML 注释：

```text
<!-- @context-fold begin search-notes -->
已完成的搜索和比较过程……
<!-- @context-fold end search-notes -->
仍需保留的结论、约束和待办写在区域外。
```

源码沿用相同核心语法，外面换成该语言的注释，例如 `#`、`//`、`/* … */`。每个标记独占一整行；带成对外壳时，开始和结束各自是一条完整注释，外壳本身不横跨整个正文。

`LABEL` 必填，同一对标记必须一致。它是 Agent 写出的简短名称，不是哈希，不必全局唯一。解析器不根据相似名称猜测配对，不补结束标记，也不尝试修复交叉或嵌套的范围。

未闭合、错配、畸形或嵌套结构不能提供可靠的折叠边界，因此保留受影响区域；嵌套中的子区也不折叠。此前独立闭合的合法区域仍可折叠。例如 A 已经闭合、B 还在生成时，只保留 B，不会让 A 的原文重新出现。错配的结束标记不能替代正确结束；孤立结束或区域外的畸形标记仅作为字面文本保留。源码注释编辑命令仍严格拒绝含损坏标记的输入，不会在这种输入上继续插入注释。

普通句子或行内字符串中的标记字样、工具参数里的字符串不构成折叠指令。普通文本按整行语法识别；要展示独占一行的字面示例而不赋予折叠意义，应给行添加非标记前缀。

## 显示与哈希

折叠后保留两个标记行，把中间正文替换为：

```text
<!-- @context-fold begin search-notes -->
[[cf:v2:0123456789ab]]
<!-- @context-fold end search-notes -->
```

上面的哈希仅为格式示例，不能拿来调用恢复工具。

对单个连续区域，SHA-256 的输入是正文的 UTF-8 字节，不含外层标记行。正文最后一个物理换行保留在引用外，也不计入正文哈希；正文中的其他空白、缩进与换行保持原样。内部保留完整 SHA-256，引用通常显示前 12 位，遇到前缀冲突时延长。只凭模糊前缀不能选择恢复对象。

正文变化就产生新的哈希；改了文件但没改标记名也一样。旧引用仍指向原快照，恢复操作不读取当前文件来冒充历史原文。短哈希标识内容，scope 标识当前会话的恢复权限，两者不能互相替代。

## 延迟

默认 `delay_requests = 1`：

| 时刻 | 可见内容 |
| --- | --- |
| Agent 只写了开始标记 | 原文。 |
| 宿主首次在完整请求中看到配对的结束标记 | 原文；记录本次完整观察。 |
| 上下文继续推进，下一次满足延迟的请求边界 | 原文已经持久保存，才显示短引用。 |

延迟以宿主能识别的请求进展计数，不使用后台计时器。同一个请求的重试不能消耗等待周期。`delay_requests = 0` 允许首次完整观察时直接投影为折叠视图；该设置仍不允许处理未闭合范围。

内容身份和出现身份分开：旧内容的相同哈希可以复用已存原文，但新一次读取必须得到新的观察机会。不能用“这个哈希以前见过”来跳过延迟。

源码适配器如果只收到一次 `tool_result`，就没有修改后续历史请求的能力。它必须保持原文，或者由宿主补齐稳定的出现身份、请求进展和历史重投影接线。接口支持标记不等于宿主已经实现延迟折叠。

独立的 [`ctxf` CLI 和 MCP](../context-folding/README.md) 另外提供显式 `fold` 操作：调用方提交文本，立即得到已保存原文的折叠视图，不需要请求周期。它不修改 `read-source` 的默认延迟；自动投影的关闭、保留和等待设置也不阻止这次明确请求的转换。`cat notes.txt | ctxf` 输出完整原始文本格式，`ctxf fold --json` 返回文本与恢复引用，`ctxf read --id ACTUAL_HASH --raw` 完整读回正文。CLI、MCP 和 SDK 使用同一个 Python 核心及选定的 SQLite 归档；MCP 返回结果后，仍由调用方决定如何使用，不能自行回写宿主历史。

## 消息与工具边界

Magpie 请求钩子可以在同一任务轮次的 Assistant 普通文本之间配对标记。跨消息时，只替换被圈定的文本切片，保留消息顺序、角色和工具调用结构。正文按切片原顺序直接拼接，不额外插入换行，工具调用/结果不进入拼接正文；恢复返回这份拼接原文，不伪造角色或消息边界。每个被替换的切片显示同一个全文引用，避免生成空消息；引用重复不表示归档正文重复。

新的用户消息是未闭合范围的边界。开始标记不能吞掉后来加入的用户要求；用户或工具输出的结束标记也不能替 Assistant 关闭范围。

工具调用名称、参数、调用 ID、普通工具结果和调用/结果配对不参加文本折叠。源码读取是独立入口：源码适配器只向同一标记规则提供已经明确提取的源文件文本，不能扫描整个工具 JSON 并从中猜测源码。恢复工具返回的正文保持可见，避免读回后立刻再次折叠。

Magpie 网关支持能核实来源的单一文本源码读取结果，对 Python 和 JavaScript/TypeScript 使用保守词法过滤，排除 docstring、普通字符串和模板字符串里的伪标记。这不是完整语言解析器；遇到 Python f-string、含歧义斜线的模板插值、JSX 或不完整字面量等情况，会保留该份源码，而非猜测注释边界。独立 Python 核心使用 Python tokenizer，JS/TS 支持使用可选 Tree-sitter 语法，能够按各自语言结构识别注释。其他语言的整行字面协议没有 lexer，可能误认多行字符串中的标记；两条接入路径都保留这一限制。

不可安全改写的签名推理、图片、音频和供应商隐藏历史不作为普通文本处理。宿主提供的历史结构不满足转换要求时，原样放行。

## 原文、存储与恢复

操作顺序固定：

1. 在当前完整输入中解析配对标记。
2. 请求历史投影确认该次出现已经满足延迟；显式 `fold` 调用无需等待。
3. 保存原文快照及其完整哈希，提交归档。
4. 返回包含短引用的请求视图。

保存、校验或提交失败，步骤 4 不执行。不能先删正文，再指望后台存档补上。磁盘文件和宿主自己的原始历史不会因请求投影而改写。

Magpie 通过 `context_folding` 的 `read` 读取实际短哈希；返回原文和完整 SHA-256。默认 `read` 保持该原文可见，`peek: true` 仅查看现有状态。分页必须沿返回的 `nextOffset` 读取，不能把 token 数、UTF-8 字节偏移、JavaScript UTF-16 单元和 Python Unicode 码点混在一起。

正文自身含有字面 `[[cf:v2:…]]` 引用时，不再将它包进另一层折叠，避免循环解释已有引用。

旧 `[[cf:v1:…]]` 归档引用属于此前的恢复协议。读取旧资料的兼容性不表示继续启用旧自动选材、三档模式、摘要层或成本批准机制。

## 恢复定位信息与 Agent 提示词

Agent 的固定提示词只需解释标记、闭合时机、区域外保留结论和按哈希恢复。该说明放在工具描述或宿主固定提示词中，不每轮重新注入教程。

请求中只更新协议 system 元数据里的恢复定位信息，格式为 `<context-folding scope=64hex />`，其中 `64hex` 表示实际的 64 位十六进制会话 scope。相同请求重放时这条元数据不累积。无法确认可调用的恢复入口时，原样保留请求，不添加定位信息。

不配置模型窗口大小，不计算或注入已用、剩余及预留上下文预算。折叠统计可以记录请求大小变化的估算，但不能据此选择内容或触发折叠。Agent 不输出标记，系统就不主动收起内容。

## 可验证的合同

实现应覆盖以下行为：配对与未闭合、损坏区域局部保留、嵌套子区不折叠、跨 Assistant 消息、用户边界、工具结构完整、延迟与重试、新出现的同内容、哈希变化、前缀冲突、完整恢复、恢复后保持、存档失败回退，以及仅含 scope 的恢复定位信息不累积。

这些是协议要求，不是测试完成声明。实际运行回执与宿主验证应分别记录，不把本地请求投影测试写成真实会话、默认 compaction 或账单节省已经验证。
