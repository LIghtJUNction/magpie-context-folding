# 文件恢复与并发一致性

原文是一份已经保存的文件快照。引用告诉 Agent 去哪里读；数据库继续保存会话、索引、延迟和统计。普通文件读取不需要启动恢复服务。

## 保存成功后才替换

请求钩子先构造候选视图，只有完整原文文件和相应状态提交成功才返回它。文件不可写、配额不足、已有内容不匹配或状态冲突时，保留原请求。不能先删正文，再靠后台补存。

Root 为普通原文物化 `<stateDir>/archives/<scope>/<text-sha256>.txt`。对话使用 `<transcript-sha256>.messages.txt` 与 `<transcript-sha256>.jsonl`；它包含原始消息对象和选择范围，其 SHA-256 用于文件校验和命名。Root 对话归档 ID 加入类型标识后另行计算，读取 CLI 使用引用 ID，校验文件使用 `sha256`，两者不要混用。`.txt` 是带来源信息的可读视图，不能把它的字节摘要误当成 JSONL 摘要。独立 Python 核心采用 `<state-file>.files/<sha256(scope)>/` 布局。

新文件先完整写入并持久化，再原子发布；遇到同名文件校验内容，不覆盖未知不同文件。目录和文件使用私有权限。持久文件发布和数据库提交不是一个跨系统事务：数据库提交失败后可能留下没有索引引用的完整文件，但不能留下已经返回、却没有完整原文的折叠引用。

数据库事务核对 revision 和原始 snapshot。异步处理期间，其他请求读取、保护或修改状态后，旧请求不能覆盖新状态。只读回调也需要验证所依赖快照。

## 直接读取与显式展开

`rg`、`grep`、原生文件读取和轻量子 Agent 可以直接读取 `.txt`；原角色、工具结构及切口以 `.jsonl` 核对。直接读取不改变原历史的折叠状态，也不增加 CLI 的恢复计数。主 Agent 只把当前任务需要的证据带回上下文。

旧 CLI `read` 和 `paste` 默认持久设置 keep；旧分组归档还会解除祖先组折叠。保护提交后才返回内容或创建导出文件。`--peek` 只查看现有状态。路径不可用或导出文件校验失败时，仍可通过 CLI 读取数据库中的原始快照；返回中省略不可用路径并标记 `fileStatus: "unavailable"`。索引查询同样可用。数据库原文也不可读时，应说明缺失，不能用当前源文件冒充旧快照。

读取类管理操作可以有限重试状态冲突。`paste` 独占创建新文件，不覆盖已有文件或符号链接；它在重试循环外执行。导出失败时，已经提交的 keep 状态不撤销。

源码恢复资料不应再被自动当作新增标记指令。重新读取完整源文件属于新的出现，有自己的延迟；读取归档中的历史文本则是按需取证。

## 保留与整理

Root 的全局存储限制计入旁侧原文文件。文件和 SQLite 都需要保留；只有索引还在，并不能保证 Agent 手中的文件路径有效。

Root `forget` 清理会话索引，不自动删除已经物化的文件。这样复制到其他地方的历史引用不会因为一次索引清理立即失效。确认某份原文已没有使用者后，才显式整理对应文件；不能把归档目录作为可任意清空的缓存。迁移目录时应考虑现有引用使用绝对路径。

旧 v1/v2 数据库、历史层和分组仍可读取，兼容恢复不意味着旧自动选材、摘要层或成本策略继续运行。

## 宿主边界

文件必须在实际 Agent 环境可访问；网关与容器没有共享路径时，引用不会自动变成可读文件。Root 的 `file_access = false` 让请求保留原文。Harbor 基准的 `read_file` 只允许读取本 trial 可信 scope 下的生成归档；模型命令仍在任务容器执行。

如果删除并重建内容、revision 都相同的会话，仅比较 snapshot 无法区分这两个生命周期；不应声称绝对跨删除隔离。直接文件读取的权限由文件系统控制，scope 不构成独立身份认证。

范围和引用合同见[折叠协议](annotation-protocol.md)。
