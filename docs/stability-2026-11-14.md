# 2026-11-14 稳定性排查

## 已复现并修复：SQLite 等锁阻塞钩子 worker

`Store.database()` 原来使用同步 `busy_timeout = 2000`。多个会话共用数据库时，单个连接等锁会阻塞 Bun 事件循环，其他钩子以及释放锁的定时器都不能及时运行。现场读取归档数据库也实际遇到了 `SQLITE_BUSY`；Magpie 日志反复报告 request hook failed or timed out，随后保留原请求。

改为 SQLite 立即返回锁竞争错误，关闭连接后通过异步退避重试，等待预算为 1 秒。只重试 `SQLITE_BUSY` / `SQLITE_LOCKED`，保留事务回滚和版本冲突检查，不重新执行调用方的投影回调。已存在的 scope 密钥直接读取，避免每次请求执行 `INSERT OR IGNORE` 争用写锁；`auto_vacuum` 仅在当前值需要改变时设置，避免重复设置也申请写锁。超过预算时继续沿用钩子的保留原请求行为。

回归测试覆盖定时释放排他锁后恢复、持续锁竞争的有限等待与事件循环响应、已有 scope 在读锁期间的查询，以及既有的并发修改/删除/统计冲突保护。
