# 归档查询与并发一致性

短哈希指向已保存的内容快照。`list`、`meta`、`grep`、`read` 查询这份归档，不重新读取当前源文件，也不把正文放回历史。前缀冲突必须报歧义，不能随意选一项。

## 先保存，再发布引用

请求钩子只有在原文、子节点关系和状态提交成功后才返回折叠视图。数据库不可写、配额不足或状态冲突时保留原请求，不能发布没有归档对象的引用。

事务核对 revision 与原始 snapshot。并发查询、清理或更新统计时，旧计算结果不能覆盖新状态；需要重试的操作有明确上限。仍被引用的父子内容必须一起保留，不能因父块折叠而清除子块。

## 查询不改变折叠状态

`read` 和 `grep` 不设置 keep，不解除父块折叠，也不改变之后的请求投影。无需 `peek` 才能做到只查询。旧接口的保留参数不应成为 Agent 的操作流程。

`read` 返回有界的节点视图：当前层正文可见，直接子块仍是引用。`meta` 返回原文哈希、大小与分页子 ID；`list --id --depth` 定位后代；递归 `grep` 在归档内访问各节点视图，返回少量带行号片段，不先把整棵树发给模型。

原文 SHA-256 与视图 SHA-256 含义不同。查询的行号、offset 和 nextOffset 都针对该节点视图。截断后的结果不代表完整原文；根据具体问题选择下一页或下一段，不自动翻完所有页面。

## 内容与出现分别计数

同内容可共享哈希和原文存储，新的出现仍有独立延迟。重复请求不推进等待计数，新 Read 不继承旧出现已经耗尽的观察机会。查询归档也不伪造新的模型请求周期。

旧数据库可能包含 v1 条目、历史层和分组。兼容读取这些数据不会恢复旧自动选材策略。legacy 导出/恢复接口若保留，只供明确维护需求；不放进模型默认工具流程。

## 当前边界

如果删除后重新创建完全相同的会话，且 revision 与 snapshot 也相同，只比较两者不能区分生命周期。不要将其表述为绝对的跨删除隔离保证。

协议、消息边界与哈希规则见 [annotation-protocol.md](annotation-protocol.md)。
