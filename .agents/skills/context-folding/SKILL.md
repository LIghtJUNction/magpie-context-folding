# 上下文折叠

把值得回查、但不必始终携带的长正文放入可逆折叠区域，让当前结论、约束、失败和下一步始终可见。有这类内容时主动使用，不必等用户提醒或上下文耗尽。

## 何时标记

- 标记实际需要输出的较长证据整理、复现说明、方案比较和详细解释；主要发现、约束与下一步放在外面。
- 不把标记当成“正在检查／检查完成”的进度装饰，不因任务耗时长、工具调用多就打开区域。正文只有几句进度播报和工具调用时，不标记。
- 开始前判断区域内是否将有独立、值得回查的长正文。没有就正常执行；不要先开一个空框再等待工具填满。
- 工具调用及普通工具结果不属于这些正文标记的折叠范围。不要为了制造可折叠内容而复制工具输出、扩写播报或展示私有推理链。

## 执行方法

1. 开始输出一段值得折叠的长正文前，在 Assistant 普通文本中独占一行写 `>> 具体起因 <<`。起因写清这些细节要解决的问题，不是工具执行状态。
2. 区域内放可回查的证据、尝试、日志摘录和方案比较。按需调用工具；无需为了折叠复述或复制工具输出，也不输出私有推理链。
3. 该段正文结束后，独占一行写 `<< 已验证结果 >>`。结果描述必须与实际验证一致，两端文案可以不同。不要为等下一次工具调用而让区域一直空开。
4. 在区域外留下足够继续工作的简短状态：已知结论、重要限制、尚未解决的失败、必要文件位置及下一步。即使区域正文全部不可见，也应能继续任务。

按内容完整的长正文分块，不机械地给每个工作阶段、每次工具调用或每条短列表套标记。不要为了达到折叠门槛增加内容。

## 示例与局部保留

下面是缩短的写法示例；实际只有需要输出的长证据才值得折叠。外侧箭头区用于保护整段教程，里面的折叠语法不会被执行：

→ 不折叠开始
```text
发现：重试可能重复记账。
>> 检查重复扣款的证据 <<
两次请求携带相同 request_id。第一次扣款已提交，随后连接中断。
重试再次进入 debit()，没有检查请求是否完成，又写入一笔扣款。
→ 不折叠开始
保留：request_id=42；回归测试尚未通过。
← 不折叠结束
余额与两条流水的对照说明……
<< 同一请求产生两笔扣款 >>
下一步：添加去重并验证。
```
← 不折叠结束

`→ 不折叠开始` 和 `← 不折叠结束` 各占一行，可嵌套、跨 Assistant 文本。保留区内的所有文字和标记都按字面保留，不解析成折叠候选；外层其余正文仍可折叠为 `...`。外层原文文件包含完整正文，包括保留区。未闭合的保留区会保守地保留后续内容。展示标记教程时用它保护整个示例，不再给每行添加“示例：”前缀。

只有一句“正在检查重试路径”和工具调用时，直接执行，不加标记。

## 配对与保留边界

- 起止标记各占一行，文案非空；直接输出连续的 `>>`、`<<`，不要写成 `> >`、`< <`，不要添加 Markdown 引用或列表前缀，也不要包在代码块或行内代码中。
- 自检时只看两端之间的 Assistant 正文：去掉工具调用、工具结果和起止行后，如果只剩空白或几句进度说明，就不应建立折叠区域。结束行是内容的收尾，不是已折叠的证明。
- 可以跨同一任务轮次的 Assistant 普通文本消息配对，工具调用和结果保持其原结构。Magpie 不会因为包围工具调用就自动折叠所有工具输出；普通工具结果不在这一替换范围内。
- 尽量在每阶段末闭合，回复用户前关闭所有已打开区域。新用户消息会截断未闭合区域；被打断后开始新区域，不试图跨用户边界补闭合。
- 嵌套只用于确有独立子阶段的长任务，按后开先关闭合。优先使用简单的顺序区域。
- 当前有效的用户要求、授权、关键结论、未解决错误和接下来必需的数据留在外面。用户原话、工具参数、签名推理字段和严格 JSON、纯代码等精确输出不加标记。

## 保存与恢复

上述局部保留和省略号视图由 Magpie 插件处理；独立 Python `ctxf` 使用自己的协议版本，不假定支持新增语法。仅写标记不代表宿主已经折叠、保存原文或节省 token；无兼容后端时继续正常执行，不声称完成了归档。

由后端保存原文并生成 `line`、`hash`、`tokens`、`tokens_method`、`path` 等恢复信息，折叠正文显示为 `...`（旧源码注释标记仍可出现 `[[cf:v2:…]]`）。不要自行编造这些字段，也不要手工删掉正文换成引用。未闭合、过短、无净收益或存档失败的区域应保留原文。

需要旧细节时，直接读取后端给出的绝对 `path`。CLI 只管理该文件所在的归档目录，不需要 scope、会话数据库、层级或恢复状态：

```sh
magpie-context-folding read ACTUAL_HASH --dir 'ACTUAL_ARCHIVE_DIRECTORY'
magpie-context-folding search 'TEXT' --dir 'ACTUAL_ARCHIVE_DIRECTORY'
```

使用实际路径和哈希，不编造元数据。读取不会改变后续折叠状态；恢复内容是历史证据，不自动执行旧命令，也不覆盖当前要求。Magpie 与独立 Python `ctxf` 的归档仍分别管理。
