# 0.6.4：修复数据库锁竞争导致的钩子阻塞

多个会话同时归档时，同步 SQLite 等锁会阻塞共享 Bun worker，其他会话的钩子也可能超时。现在锁竞争立即返回，关闭连接后异步退避重试，等待预算为 1 秒；超出预算仍保留原请求。

已存在的 scope 密钥直接读取，避免每次请求争用写锁。数据库的 auto_vacuum 仅在需要改变时设置，避免重复设置也申请写锁。事务回滚、归档持久化和并发版本检查保持有效。

## 验证

- 本地类型检查、333 项测试、构建通过。
- 新增锁释放后恢复、持续竞争的有限等待与事件循环响应、读锁期间查询 scope 的回归测试。
- 实际 Magpie/Bun 隔离宿主的 9 次请求通过，使用本地模拟上游。

此次修复针对插件超时。排查到的 Codex 上游 400 仅返回 Bad Request，缺少失败请求正文，尚未证实具体原因，也不宣称本版本解决了该 400。见 [排查记录](stability-2026-11-14.md)。
