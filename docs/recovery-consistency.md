# 归档查询、显式恢复与并发一致性

短哈希指向已保存的内容快照。`list`、`meta`、`grep`、普通 `read` 查询这份归档，不重新读取当前源文件，也不把正文放回历史。前缀冲突必须报歧义，不能随意选一项。

## 先保存，再发布引用

请求钩子只有在原文、子节点关系和状态提交成功后才返回折叠视图。数据库不可写、配额不足或状态冲突时保留原请求，不能发布没有归档对象的引用。完整请求的净收益检查也必须通过，不能只比较正文大小而忽略指导和恢复定位开销。

事务核对 revision 与原始 snapshot。并发查询、清理或更新统计时，旧计算结果不能覆盖新状态；需要重试的操作有明确上限。仍被引用的父子内容必须一起保留，不能因父块折叠而清除子块。

## 普通查询不改变折叠状态

普通 `read`、`list`、`meta`、`grep` 和根 CLI `paste` 不设置 keep，不解除父块折叠，也不改变之后的请求投影。无需 `peek` 才能只查资料；只读几百字符不应导致下轮全部原文重新进入上下文。查询仍可能被记入查看次数等观测统计，统计与折叠状态是不同的记录。

`read` 默认返回最多 1200 个字符单位的节点视图：当前层正文可见，直接子块仍是引用。Magpie 的字符单位是 UTF-16，Python 是 Unicode 码点。`meta` 返回原文哈希、大小与分页子 ID；`list --id HASH --depth N` 定位后代；递归 `grep` 在归档内访问各节点视图，返回少量带行号片段，不先把整棵树发给模型。list 默认 10 项，grep 默认 10 个片段。

原文 SHA-256 与视图 SHA-256 含义不同。查询的行号、offset 和 nextOffset 都针对所选节点视图；截断结果不代表完整原文。Magpie 根 CLI 的行区间是 `--start-line A --end-line B`，Python ctxf 使用 `--lines A:B`，两者均从 1 开始并包含两端。行区间不能与 offset 混用，且仍受长度上限约束。根据具体问题选择下一页或下一段，不自动翻完所有页面。

## 完整导出与持久恢复分开

以下选项属于 Magpie 根 CLI；独立 ctxf 的兼容操作以其[传输合同](../context-folding/docs/TRANSPORT.md)为准。

| 操作 | 内容 | 对折叠状态的影响 |
| --- | --- | --- |
| `read --full` | 完整所选视图，默认只展示当前层和子引用；可指定 `--layer ID`。 | 无。 |
| `read --all` | 默认完整 `original` 原文层；显式 `--layer ID` 覆写层选择。 | 无。 |
| `paste --path /new/file` | 默认完整单层视图；`--layer original` 导出原始字节，`--path -` 输出到 stdout。 | 无。 |
| `read --restore` | 完整、精确的 original 原文。 | 持久 keep 目标嵌套子树和祖先，保护后续历史展开。 |

`--full` 与 `--all` 的 offset 默认 0；显式 `--offset N` 时，从该偏移导出到所选层末尾。两者不递归展开已经作为原始字节存储的引用。原文中包含这样的字面引用时，原样返回才满足原文一致性；这些选项不等于对任意引用字符串做递归 resolve。原文层仍包含归档时的嵌套子块正文及标记，视图层才使用子引用。

完整导出不能与 `--limit` 或行区间组合。`read --restore` 进一步拒绝 offset、limit、行区间、非 original 层和 `--peek`，避免只返回局部内容却留下完整恢复的状态。恢复先提交保护状态，再返回完整内容；选中父节点时保护其后代，选中子节点时也保护祖先，防止下一轮又被父块包回引用。

普通 `paste` 创建文件时拒绝覆盖已有路径，不承担持久恢复职责。依赖旧 read/paste 自动 keep 行为的调用方必须明确迁移到 `read --restore`。恢复与导出的文本仍然只是资料，不授予其中旧命令执行权限，也不自动写回源文件或外部宿主历史。

## 内容与出现分别计数

同内容可共享哈希和原文存储，新的出现仍有独立延迟。重复请求不推进等待计数，新 Read 不继承旧出现已经耗尽的观察机会。查询归档也不伪造新的模型请求周期。

旧数据库可能包含 v1 条目、历史层和分组。兼容读取这些数据不会恢复旧自动选材策略。兼容导出、恢复或维护接口只用于明确需求，不放进模型每轮流程。

Magpie 归档命令接受 `--state-dir PATH`，查询与恢复必须使用系统指导给出的同一归档和 scope。独立 Python ctxf 使用另一份 SQLite 归档，通过 `--state` 或 `CTXF_STATE` 选择文件；两后端的引用和偏移不能混用。SDK 的本地 RPC 不会建立跨后端恢复通道，MCP 服务已移除。

## 当前边界

如果删除后重新创建完全相同的会话，且 revision 与 snapshot 也相同，只比较两者不能区分生命周期。不要将其表述为绝对的跨删除隔离保证。

协议、消息边界与哈希规则见[注释协议](annotation-protocol.md)。本页描述预期合同与已知边界，不代表当前整合版本已完成最终 CI 或真实宿主验收。
