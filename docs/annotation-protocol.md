# Magpie 文本折叠协议

## 折叠与局部保留

在 Assistant 普通文本中，用独占一行的 `>> 具体起因 <<` 和 `<< 已验证结果 >>` 包住需要输出的长证据、比较或解释。两端描述可以不同。当前结论、约束、未解决错误和下一步留在外面。

`→ 不折叠开始` 与 `← 不折叠结束` 保护中间内容：文字与标记按字面保留，外层其余正文仍可折叠。可嵌套、跨 Assistant 文本；未闭合时保守地保留后续内容。保留区不会替工具调用赋予正文身份，用户消息仍是配对边界。

下面整个示例处于保留区，内部箭头演示局部保留：

→ 不折叠开始
```text
结论：重试可能重复记账。
>> 检查重试证据 <<
需要呈现的长证据……
→ 不折叠开始
保留：request_id=42；回归测试尚未通过。
← 不折叠结束
其他长证据……
<< 已定位重复扣款路径 >>
下一步：添加去重并验证。
```
← 不折叠结束

正文足够长、净收益达标且归档成功后，视图如下（路径、哈希等由插件生成）：

→ 不折叠开始
```text
结论：重试可能重复记账。
>> 检查重试证据 <<
line:原始正文行数
hash:完整原文哈希
tokens:估算值
tokens_method:utf8-bytes/4-ceil
path:/实际目录/archive/完整原文哈希.txt
...
→ 不折叠开始
保留：request_id=42；回归测试尚未通过。
← 不折叠结束
...
<< 已定位重复扣款路径 >>
下一步：添加去重并验证。
```
← 不折叠结束

元数据属于整个外层原文，包含保留区；不为每个省略号创建不同文件。文件内容是精确 UTF-8 原文，不含外层起止行和正文最后的物理换行。保留区及其标记也完整归档。相同原文复用 SHA-256 文件；需要时直接读取 `path` 即可。

`line` 包含正文空行，`tokens` 是 UTF-8 字节数除以 4 向上取整的估算。元数据、保留内容与省略号的实际开销计入收益门槛。未闭合、错配、过短、无净收益或持久化失败时保留原文。插件只修改发送给模型的请求视图，不改用户历史和源文件。重复投影不再归档元数据。

标记不能带 Markdown 引用或列表前缀，也不能把 `>>` 拆成 `> >`。不要用空标记包围工具调用或进度播报；普通工具结果不会因位于两端之间就被折叠。

## 原文目录与 CLI

原文文件名为 `<完整 SHA-256>.txt`，位于所配置存储目录的 `archive/` 中。原子保存并校验成功后才发布折叠视图。文件独立于会话数据库保留，不因会话清理自动删除。

```sh
magpie-context-folding stats --dir /实际归档目录
magpie-context-folding list --dir /实际归档目录 --sort size --order desc
magpie-context-folding search '关键字' --dir /实际归档目录
magpie-context-folding read 实际哈希 --dir /实际归档目录
magpie-context-folding clean --older-than 30 --dir /实际归档目录
```

CLI 仅管理普通哈希 `.txt` 文件，忽略符号链接和其他文件。`read` 原样输出完整文件；`search` 是字面文本搜索。`clean` 默认预览，加 `--apply` 才删除。CLI 不读取会话数据库，不接受 scope、恢复层级或 keep 状态；读取不会让历史自动展开。目录已知时也可直接使用系统文件工具。

## 兼容边界

原有 `@context-fold begin/end LABEL` 源码注释和对话标记继续兼容，仍可显示 `[[cf:v2:HASH]]`；相同注释外壳和标签必须配对。源码的字符串伪标记识别继续沿用各语言的保守解析。

新箭头保留区和 `...` 视图属于 Magpie 插件。独立 Python `ctxf` 仍使用自己的归档、CLI 和引用协议，不与 Magpie 互换数据库或恢复参数。源码注释编辑与内部历史节点 API 不因根目录 CLI 精简而改变。
