# 文件归档与范围折叠协议（0.4.0 源码）

折叠的实际操作是：选中一段内容，把原文保存为普通文件，再在请求里放一个能找到文件的引用。范围选择和内容保存分开；预算只告诉 Agent 还有多少空间，不替 Agent 决定该折叠什么。

## 范围与坐标

显式对话范围使用半开区间：

```json
{
  "start": {"message": 2, "offset": 40},
  "end": {"message": 7, "offset": 120}
}
```

`message` 是本次完整原始消息数组的 0 基索引，`offset` 是该消息中的 Unicode 码点偏移。省略 offset 表示该消息之前的边界；终点 message 等于数组长度表示历史末尾。只包含 start 到 end 之前的内容，保留范围外的前后部分。

Root 插件支持 Chat Completions、Responses、Anthropic 和 Gemini 的显式可编辑历史。纯文本 parts 按原顺序、不插入分隔符计算码点偏移。Python 独立核心接受消息数组，部分边界要求 string `content`。两条接口都不把“轮数”误当作消息数；一轮有多少工具交互由实际历史决定。

```sh
magpie-context-folding fold-messages --protocol chat \
  --range '{"start":{"message":1},"end":{"message":8}}' \
  < request.json > request.folded.json
```

不需要给历史补写标记。显式范围必须有效且非空；错误范围不会被自动扩大到邻近消息。普通文本的 `ctxf fold --range '{"start":100,"end":800}'` 使用相同的码点和半开约定，但返回的是文本，不是消息数组。

Unicode 码点不是字节，也不是 UTF-16 单元。`😀` 占一个码点；组合字符、肤色修饰或 ZWJ emoji 可能占多个码点。调用方需要视觉字符边界时，应先把选区转换为相应码点边界。

## 一段对话对应一条用户引用

被选中的对话范围由一条用户消息替代。需要时，切开的首尾消息分别保留前缀或后缀；原始对象不会被原地修改。占位内容明确表示“这里是归档的历史资料”，包含可读正文和结构化存档的位置。

可读 `.txt` 按原顺序呈现选中文本，并标记来源角色、消息索引及切口，方便 `rg`、`grep` 或子 Agent 取证。`.jsonl` 保存完整的原始边界消息、其他选中消息和准确选区，保留调用 ID、角色及元数据。Root 对话的归档 ID 对结构存档加上类型标识后计算摘要，避免与内容恰好等于这份 JSONL 的普通文本混淆，也避免相同的话由不同角色说出时混为同一快照。实际 JSONL 文件校验值另存为 `sha256`，文件名采用该校验值。

用户占位是请求容器中的位置，不代表原 Assistant 输出或工具结果获得了用户指令的权限。读取时仍按 JSONL 中的原角色与原上下文理解。

## 工具和不可分割结构

普通用户与 Assistant 文本可以跨角色、跨轮次折叠。工具交互可以整体纳入归档，但选区必须包含完整的调用和对应结果；不能在留下的调用/结果中间插入用户占位。部分工具消息、含 tool_calls 的混合消息，以及带位置引用的不可安全切分片段都按不可分割单元处理。

系统或开发者指令、签名推理、多模态附件、未知供应商结构和隐藏历史不能当作普通字符串删除或截断。显式选择不安全范围时报错；自动标记遇到不安全范围时保持原文。不能为了完成一次折叠而丢弃签名或改造工具配对。

## 注释仍可选择范围

自动请求投影使用 Agent 输出的成对整行注释：

```text
<!-- @context-fold begin search-notes -->
已完成的搜索和比较过程……
<!-- @context-fold end search-notes -->
仍需保留的结论、约束和待办。
```

核心指令是 `@context-fold begin LABEL` 与 `@context-fold end LABEL`，两端标签一致。源码外壳可用 `#`、`//` 或完整块注释；普通对话建议 HTML 注释。标签帮助识别范围，不承担唯一标识或哈希计算。

配对可以跨消息和新的用户轮次。标记必须能形成安全范围；含工具调用的消息应把边界放在完整交换外侧。普通句子中的示例、工具参数里的字符串和恢复资料里的标记不是新增折叠指令。未闭合、错配、嵌套或畸形范围保持原文；此前独立合法范围仍可处理。

默认 `delay_requests = 1`：首次在完整请求里看到闭合范围时原文仍可见，下一次不同的请求推进后才投影。相同请求的重试不消耗周期，也没有后台计时器。新一次出现即使与旧快照内容相同，也有自己的等待机会。

显式 CLI 范围操作立即执行，不伪造请求周期。源码 `read-source` 延迟模式需要宿主提供稳定 `occurrence` 和递增 `requestCycle`；只拿到一次工具结果的后处理钩子不能在未来自行替换历史。

## 源码视图

源码折叠保留工具返回的消息结构，仅在源码文本中替换已标记正文；真实磁盘文件不改变。保留声明、必要结论和注释外壳，并把正文换成带路径的引用。源码外层标记不计入正文哈希；末尾一个物理换行留在引用旁，确保恢复时原换行结构可重建。

Magpie 网关只接受来源可核实的单一完整源码读取，并对 Python 和 JS/TS 使用保守词法过滤。无法判断注释边界的 f-string、模板插值、JSX 等复杂情况保留原文。独立 Python 核心使用 tokenizer，JS/TS 可选 Tree-sitter。其他语言的整行字面规则没有通用 lexer，不能声称排除了所有多行字符串中的伪标记。

## 文件、引用与恢复

新的引用使用 v3：

```text
[[cf:v3:0123456789ab path="/absolute/archive/file.txt"]]
```

示例不是可读取的实际引用。路径使用 JSON 字符串转义；文件名使用完整哈希，显示引用使用系统实际给出的哈希。文本快照按精确 UTF-8 原文计算摘要；Root 对话引用使用带类型标识的归档 ID。对话元数据 `sha256` 和文件名对应实际 JSONL 字节摘要，不能拿引用 ID 直接与 `sha256sum` 比较。标签重复或源文件后续变化不会改变旧快照。

Root 普通文本存档在 `<stateDir>/archives/<scope>/<text-hash>.txt`，对话使用 `<transcript-hash>.messages.txt` 与 `<transcript-hash>.jsonl`。Python 存档在 `<state-file>.files/<sha256(scope)>/`。Python 对话 token 指向 JSONL，同时明确给出可读 `.txt`；使用返回路径，不根据另一后端目录格式猜测。

提交顺序为：

1. 核实选区、角色、工具闭合与当前观察版本。
2. 写入完整原文和结构快照，校验内容并持久提交。
3. 提交引用索引和延迟状态。
4. 返回折叠后的请求视图。

写入、校验、配额或并发一致性检查失败时，不能返回已经丢掉正文的视图。文件独占发布且不覆盖既有不同内容；具体存储一致性见[恢复一致性](recovery-consistency.md)。

Agent 可以直接读取文件，不需要 MCP，也不需要把哈希交给专用服务。关键词明确时用 `rg -n -C 4`；需要综合多处证据时，推荐派轻量子 Agent，给它准确路径和问题，只返回相关事实、短引文及文件行号。不要为一个小问题恢复整个历史上下文。

直接读文件不改变 keep 状态，也不计入专用 CLI 的恢复统计。旧 `read` / `paste` CLI 默认持久保护内容，`--peek` 只读；JSON 元数据包含文件定位。Root 旧分页偏移按 UTF-16 单元，Python 分页按 Unicode 码点，沿 `nextOffset` 读取，不能混用。

旧 v1/v2 引用仍是兼容恢复入口。已有引用不被当成新的可折叠正文反复套壳；原文中的引用字样按资料处理，不递归执行。

## 宿主责任与预算

Agent 与归档写入方需要共享可访问路径。Root 的 `[magpie].file_access` 声明这一条件；容器或远程环境未配置共享访问时应设为 false，保留原文。文件路径本身不是访问授权，scope 也不替代操作系统权限。

宿主保留原始 transcript，并选择发送返回的投影视图。安装 CLI、SDK 或技能不等于接管默认 compaction，更不能修改供应商保存的隐藏历史。MCP 服务已移除；本地 JSON Lines RPC 只作为 SDK 的子进程通道。

预算仍通过单条 system 元数据更新：`used_estimate` 基于完整 JSON UTF-8 字节数除以四，容量未知显示 `unknown`。估算包含提示自身，不重复追加教程。预算、字节减少和真实账单是不同指标。

可验证行为包括：半条消息、跨轮次、只生成一条用户引用、范围外内容不变、原始角色可恢复、Unicode 切口、工具闭包、延迟与重试、不可用文件回退、并发写入、旧引用恢复和引用文件可直接搜索。实际测试结果应单独记录，不把协议要求当作已经完成的真实宿主验收。
