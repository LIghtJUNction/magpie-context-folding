# 原文恢复与并发一致性

短哈希指向一次已经保存的内容快照。恢复不能重新读取源文件来替代旧快照，也不能把前缀冲突处理成“随便取第一条”。完整 SHA-256 用于确认原文，scope 限定可恢复的会话。

本文描述根 Magpie 插件的请求钩子和工具。独立 Python 核心使用自己的归档，其默认读取后保护语义不因本次 Magpie 的 `read`/`restore` 区分而变化。

## 保存成功后才替换

请求钩子先构造候选视图，检查完整请求的净减少估算，在原文和状态提交成功后才返回它。收益预审不通过的候选不会建立新正文归档条目；满足等待周期的实际批次还需要独立通过收益检查。数据库不可写、配额不足或状态冲突时，返回原请求。延迟状态不能先于原文独立提交，从而制造一个没有恢复对象的引用。

存储事务同时核对 revision 和原始 snapshot。异步处理期间有其他请求读取、保护、清理或更新统计时，旧结果不能覆盖较新的状态。即使回调没有修改内容，也需要验证所依据的快照仍有效。

## 查阅与保持展开

`read` 默认查阅一页原文，`paste` 默认将原文导出到新文件，两者都不改变已有折叠或保护状态。省略 `peek` 等同于 `peek:true`；正常查阅不会把原条目永久标记为 keep，也不会解除祖先分组的折叠。

`restore` 显式将原文保护为 keep；对于旧分组归档，还会解除其祖先组的折叠。原有 `read`/`paste` 调用显式传 `peek:false` 仍执行相同保护。保护提交后才返回内容或创建目标文件，后续再次查阅不会撤销它。历史层或内容别名的保护继续作用于对应原文及其祖先。

读取类工具可在冲突后重新读取当前快照，次数有界。`paste` 的文件创建放在重试循环之外，使用独占创建；已有文件或符号链接不被覆盖。显式 `peek:false` 的文件创建失败可能发生在原文已经保护之后，保护不会因此撤销；默认导出不主动设置该保护。

恢复输出不再次参加折叠，避免 Agent 查原文时生成另一个待恢复引用。工具 `read`/`restore` 默认一页最多 2,000 个 UTF-16 单元，返回 `nextOffset` 继续读取；返回内容本身仍会占用后续上下文，默认只读并不意味着读取没有成本。

`status` 默认简要返回最近决策和统计概况，`detail:true` 才携带完整指标；`list` 和 `status` 都不会解除折叠。`forget` 仍拒绝删除带有活跃折叠条目或分组的归档；需要清理时先显式 `restore` 对应条目或分组，普通 `read` 不再隐式满足这个前提。

## 内容与出现分别计数

同内容可共享哈希及原文存储，但一次新的出现有自己的延迟。请求重试不应推进等待计数，重新读取同一文件也不应继承旧出现已经耗尽的保留周期。

旧数据库可能仍包含 v1 条目、历史层和分组。兼容读取这些原文与引用，不会重新启动自动摘要、版本候选选择或旧模式。

## 当前边界

如果删除并重新创建了内容完全相同、revision 也相同的会话，仅比较 snapshot 无法区分这两个生命周期。这一边界不应被表述成绝对的跨删除隔离保证。
