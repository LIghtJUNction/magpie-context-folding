# 0.6.2：闭合标记直接折叠

有效标记闭合并成功归档后直接折叠，不再按正文长度、token 数或恢复信息开销决定是否执行。取消单块与整批净收益检查；旧 min_savings_tokens / minSavingsTokens 仅兼容读取，不再影响折叠。默认 delay_requests=0，首次观察到完整标记即可折叠；显式设置的等待周期、保留区和用户边界继续生效。

原文文件仍先持久化，再发布折叠视图。复用已有归档时，校验精确字节并同步文件与目录；同步失败会报错。归档文件在 SQLite 写锁内、配额及版本冲突检查之后发布，事务失败时清理本次新建文件并保留原有归档。这不是跨数据库与文件系统的原子事务，进程突然终止仍可能留下未提交文件。
