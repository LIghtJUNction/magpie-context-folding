# 原文恢复与并发一致性

新 v3 引用指向某个出现位置的完整节点 ID；内容 SHA-256 负责确认和去重原文。恢复不能重新读取源文件来替代旧快照，也不能把旧内容哈希对应的多个位置处理成“随便取第一个父节点”。scope 限定可查询的会话。

## 保存成功后才替换

请求钩子先构造候选视图，在原文和状态提交成功后才返回它。数据库不可写、配额不足或状态冲突时，返回原请求。延迟状态不能先于原文独立提交，从而制造一个没有恢复对象的引用。

存储事务同时核对 revision 和原始 snapshot。异步处理期间有其他请求读取、保护、清理或更新统计时，旧结果不能覆盖较新的状态。即使回调没有修改内容，也需要验证所依据的快照仍有效。

## 查看与持久恢复分开

根插件 CLI 和内部 API 的 `read` 默认有界查看，不解除折叠；`--all` 才读取全文，`--restore` 才将原文保护为 keep 并解除包含它的祖先折叠。只读几百字符不应导致下轮全部原文重新进入上下文。`list`、`search`、`grep` 与 `meta` 也不修改归档状态。

旧客户端依赖 `read` 隐式恢复时，必须改用显式恢复操作。根插件 CLI `paste` 默认也只导出，不解除折叠；需要保护时，显式请求恢复，先提交保护状态，再返回内容或创建目标文件。

读取类工具可在冲突后重新读取当前快照，次数有界。`paste` 的文件创建放在重试循环之外，使用独占创建；已有文件或符号链接不被覆盖。创建失败可能发生在原文已经保护之后，保护不会因此撤销。

恢复输出不再次参加折叠。否则 Agent 查原文会生成另一个待恢复引用，造成重复回查。

## 内容与出现分别计数

同内容可共享哈希及原文存储，但一次新的出现有独立节点、父节点、原始范围和延迟。请求重试不应推进等待计数，重新读取同一文件也不应继承旧出现已经耗尽的保留周期。新节点的关系只依据原文范围建立；不猜测旧 hash-only 归档曾经出现过的具体位置。

Python 归档加载时兼容旧的内嵌原文 JSON，在下一次成功写入时把正文转存到同一 SQLite 文件的 blobs 表。迁移和节点保存使用同一事务；失败回滚，旧归档仍然可以读取。纯查询不触发迁移或垃圾回收。

旧数据库可能仍包含 v1 条目、历史层和分组。兼容读取这些原文与引用，不会重新启动自动摘要、版本候选选择或旧模式。

## 当前边界

如果删除并重新创建了内容完全相同、revision 也相同的会话，仅比较 snapshot 无法区分这两个生命周期。这一边界不应被表述成绝对的跨删除隔离保证。
