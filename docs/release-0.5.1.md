# magpie-context-folding 0.5.1

本版改进主动折叠指导：每完成一个里程碑，先保留可独立理解的块外摘要，再折叠较长的支撑细节。指导词同时缩短，避免提示词开销抵消折叠收益。

- 结论、约束、失败和下一步保留在块外；任务外层块作为可选归组，依据多里程碑回放结果使用。
- 随仓库维护的 Python 核心补齐 `ctxf post-compact`，并更新压缩后的提醒。这部分不包含在根 npm 插件中。
- 新增可复现的四种折叠策略回放、已安装 npm 包的隔离宿主 smoke，以及原始基准记录。
- 修复 CI 宿主 smoke 在运行 CLI 前缺少构建步骤的问题。

## 安装

```sh
magpie plugin add npm:magpie-context-folding@0.5.1
```

本版延续 0.5.0 的 CLI 恢复接口和配置。保留已有归档，避免同时加载同一插件的源码和 npm 副本。

## 验证与基准

发布前完成本地类型检查、255 项 Bun 测试和构建。相同运行时代码已通过 18 项真实 Magpie/Bun 隔离宿主检查、Python 压缩提醒与 CLI 定向测试，以及 8 个 Harbor smoke trials。

多里程碑回放中，逐里程碑折叠发送 171,190 B，任务外层加里程碑折叠发送 170,983 B。后者只多省 207 B，累计前缀失效约多 1 KB。Harbor 合成轨迹中 baseline 发送 91,108 B，folding 发送 89,408 B。方法、完整数据和复现命令见 [README 基准](../README.md#可复现基准)。

这些实验使用合成消息；请求公共字节前缀是缓存变化的代理，不能当作供应商 cached tokens、真实模型质量或账单节省的证据。sub2api 缓存问题仍待脱敏请求与 usage 数据复现。
