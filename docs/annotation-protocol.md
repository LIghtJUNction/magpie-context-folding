# 注释主动折叠协议（0.4.0）

折叠是一项明确的文本替换：Agent 写出开始与结束标记，宿主保存中间的原文，再在后续请求中用可恢复的短引用替换它。系统不判断内容是否“过时”，也不因预算紧张自动选择候选内容。Magpie 请求钩子还检查整批替换的净收益；标记表示允许折叠，不保证任何长度的内容都值得折叠。

本页的共享部分是标记、快照和引用协议。收益门槛、请求提示、`read`/`restore` 的默认行为明确属于 Magpie 插件；独立 Python `ctxf` 的差异单独注明。

## 标记

核心语法只有两行：

```text
@context-fold begin LABEL
@context-fold end LABEL
```

在聊天文本中，建议使用完整 HTML 注释：

```text
<!-- @context-fold begin search-notes -->
已完成的搜索和比较过程……
<!-- @context-fold end search-notes -->
仍需保留的结论、约束和待办写在区域外。
```

上述文字只展示语法。实际使用围绕任务中自然产生的长过程，不额外制造短笔记或扩写内容来触发插件。

源码沿用相同核心语法，外面换成该语言的注释，例如 `#`、`//`、`/* … */`。每个标记独占一整行；带成对外壳时，开始和结束各自是一条完整注释，外壳本身不横跨整个正文。

`LABEL` 必填，同一对标记必须一致。它是 Agent 写出的简短名称，不是哈希，不必全局唯一。解析器不根据相似名称猜测配对，不补结束标记，也不尝试修复交叉或嵌套的范围。

未闭合、错配、畸形或嵌套结构不能提供可靠的折叠边界，因此保留受影响区域；嵌套中的子区也不折叠。此前独立闭合的合法区域仍可折叠。例如 A 已经闭合、B 还在生成时，只保留 B，不会让 A 的原文重新出现。错配的结束标记不能替代正确结束；孤立结束或区域外的畸形标记仅作为字面文本保留。源码注释编辑命令仍严格拒绝含损坏标记的输入，不会在这种输入上继续插入注释。

普通句子或行内字符串中的标记字样、工具参数里的字符串不构成折叠指令。普通文本按整行语法识别；要展示独占一行的字面示例而不赋予折叠意义，应给行添加非标记前缀。

## 显示与哈希

折叠后保留两个标记行，把中间正文替换为：

```text
<!-- @context-fold begin search-notes -->
[[cf:v2:0123456789ab]]
<!-- @context-fold end search-notes -->
```

上面的哈希仅为格式示例，不能拿来调用恢复工具。

对单个连续区域，SHA-256 的输入是正文的 UTF-8 字节，不含外层标记行。正文最后一个物理换行保留在引用外，也不计入正文哈希；正文中的其他空白、缩进与换行保持原样。内部保留完整 SHA-256，引用通常显示前 12 位，遇到前缀冲突时延长。只凭模糊前缀不能选择恢复对象。

正文变化就产生新的哈希；改了文件但没改标记名也一样。旧引用仍指向原快照，恢复操作不读取当前文件来冒充历史原文。短哈希标识内容，scope 标识当前会话的恢复权限，两者不能互相替代。

## Magpie 的净收益检查

请求钩子解析允许折叠的区域后，先模拟整批候选替换。设 `T(x) = ceil(JSON(x) 的 UTF-8 字节数 / 4)`，则：

```text
net = T(清理旧提示后的输入请求) - T(替换后的完整输出请求)
accept = net >= max(1, min_saving_tokens)
```

`min_saving_tokens` 默认为 256，插件 option 为 `minSavingTokens`。输出请求包括所有引用、协议包装、恢复 scope，以及启用时的预算提示。因此多个候选共同承担一次提示开销；门槛不等于每个块的最短长度。

预审不通过时，不为被拒绝的候选新增正文归档或延迟记录，原文保留。最近决策用 `insufficient-savings`、`skippedRegions`、`potentialSavingTokensEstimated` 说明原因。只看短正文是否比哈希长，不能代替这个完整请求检查。

满足延迟后，仅将本次成熟候选组成实际批次，再检查一次完整请求的净减少估算。仍在等待的候选不能补贴成熟批次；被拒绝的实际批次不会标记为已经折叠或增加折叠计数。预审阶段已经建立的等待归档仍可保留。

设为 0 仍不接受零或负的净减少估算。估算不等于精确 token、真实费用或任务表现，也不抵扣未来回查产生的工具输出。此门槛只处理有标记的区域，不选择未标记的历史。

## 延迟

默认 `delay_requests = 1`：

| 时刻 | 可见内容 |
| --- | --- |
| Agent 只写了开始标记 | 原文。 |
| 宿主首次在完整请求中看到配对的结束标记，且候选批次通过收益预审 | 原文；记录本次完整观察。 |
| 上下文继续推进，下一次满足延迟且成熟批次通过收益检查 | 原文已经持久保存，才显示短引用。 |

延迟以宿主能识别的请求进展计数，不使用后台计时器。同一个请求的重试不能消耗等待周期。`delay_requests = 0` 允许首次完整观察时直接投影为折叠视图；该设置仍要求收益检查通过，也不允许处理未闭合范围。普通任务进展就会推进周期，不需要专门调用状态工具。

内容身份和出现身份分开：旧内容的相同哈希可以复用已存原文，但新一次读取必须得到新的观察机会。不能用“这个哈希以前见过”来跳过延迟。

源码适配器如果只收到一次 `tool_result`，就没有修改后续历史请求的能力。它必须保持原文，或者由宿主补齐稳定的出现身份、请求进展和历史重投影接线。接口支持标记不等于宿主已经实现延迟折叠。

独立的 [`ctxf` CLI 和 MCP](../context-folding/README.md) 另外提供显式 `fold` 操作：调用方提交文本，立即得到已保存原文的折叠视图，不需要请求周期，也不使用 Magpie 的完整请求收益门槛。它不修改 `read-source` 的默认延迟；自动投影的关闭、保留和等待设置也不阻止这次明确请求的转换。`cat notes.txt | ctxf` 输出完整原始文本格式，`ctxf fold --json` 返回文本与恢复引用，`ctxf read --id ACTUAL_HASH --raw` 完整读回正文。CLI、MCP 和 SDK 使用同一个 Python 核心及选定的 SQLite 归档；MCP 返回结果后，仍由调用方决定如何使用，不能自行回写宿主历史。

## 消息与工具边界

Magpie 请求钩子可以在同一任务轮次的 Assistant 普通文本之间配对标记。跨消息时，只替换被圈定的文本切片，保留消息顺序、角色和工具调用结构。正文按切片原顺序直接拼接，不额外插入换行，工具调用/结果不进入拼接正文；恢复返回这份拼接原文，不伪造角色或消息边界。每个被替换的切片显示同一个全文引用，避免生成空消息；引用重复不表示归档正文重复。

新的用户消息是未闭合范围的边界。开始标记不能吞掉后来加入的用户要求；用户或工具输出的结束标记也不能替 Assistant 关闭范围。

工具调用名称、参数、调用 ID、普通工具结果和调用/结果配对不参加文本折叠。源码读取是独立入口：源码适配器只向同一标记规则提供已经明确提取的源文件文本，不能扫描整个工具 JSON 并从中猜测源码。恢复工具返回的正文保持可见，避免读回后立刻再次折叠。

Magpie 网关支持能核实来源的单一文本源码读取结果，对 Python 和 JavaScript/TypeScript 使用保守词法过滤，排除 docstring、普通字符串和模板字符串里的伪标记。这不是完整语言解析器；遇到 Python f-string、含歧义斜线的模板插值、JSX 或不完整字面量等情况，会保留该份源码，而非猜测注释边界。独立 Python 核心使用 Python tokenizer，JS/TS 支持使用可选 Tree-sitter 语法，能够按各自语言结构识别注释。其他语言的整行字面协议没有 lexer，可能误认多行字符串中的标记；两条接入路径都保留这一限制。

不可安全改写的签名推理、图片、音频和供应商隐藏历史不作为普通文本处理。宿主提供的历史结构不满足转换要求时，原样放行。

## 原文、存储与恢复

Magpie 请求钩子的操作顺序固定：

1. 在当前完整输入中解析配对标记。
2. 预审整批净收益，通过后建立原文与出现记录；等待时保留原文。
3. 确认本次实际折叠批次已经满足延迟，并再次检查其完整请求净收益。
4. 保存原文快照、完整哈希及折叠状态，提交归档。
5. 返回包含短引用的请求视图。

保存、校验或提交失败，步骤 5 不执行。不能先删正文，再指望后台存档补上。磁盘文件和宿主自己的原始历史不会因请求投影而改写。独立 Python 的显式 `fold` 不经过 Magpie 的延迟和完整请求收益检查，但同样必须先保存原文，才能返回引用。

Magpie 通过 `context_folding` 的 `read` 查阅实际短哈希，默认返回不超过 2,000 个 UTF-16 单元的一页及完整原文的 SHA-256，不取消已有折叠。`restore` 才显式保护原文，解除旧式祖先分组的折叠，并返回同样的分页内容。`paste` 默认只导出新文件；`read`/`paste` 仍接受 `peek:false` 以兼容明确要求保护的旧调用。省略 `peek` 或传 `true` 都不改变已有折叠或保护状态。

分页必须沿返回的 `nextOffset` 读取，不能把 token 数、UTF-8 字节偏移、JavaScript UTF-16 单元和 Python Unicode 码点混在一起。返回的页会进入工具结果并保持可见，因此按需读取仍会影响实际上下文占用。根插件 CLI 的 `read` 默认完整输出 stdout，`--limit` 才限定一页；这个管道合同不改变工具默认分页或默认只读的行为。

Python 独立核心保留默认读取后保护原文、`--peek` 只查看的合同。本次 Magpie 的 `restore` action 与默认变化不自动扩展为 Python 工具能力。

正文自身含有字面 `[[cf:v2:…]]` 引用时，不再将它包进另一层折叠，避免循环解释已有引用。

旧 `[[cf:v1:…]]` 归档引用属于此前的恢复协议。读取旧资料的兼容性不表示继续启用旧自动选材、三档模式、摘要层或成本批准机制。

## 预算与 Agent 提示词

Agent 的固定提示词只需解释真实长过程的标记、闭合时机、区域外保留结论和按需回查。该说明放在工具描述或宿主固定提示词中，不每轮重新注入教程。无需按 `status → stats → list → read` 走一套流程；已知引用直接 `read`，查到所需信息后继续原任务。

Magpie 请求中的动态提示写在协议 system 元数据中，按以下条件决定：

| 当前情况 | 动态提示 |
| --- | --- |
| 未配置模型窗口，无当前折叠引用 | 不追加。 |
| 未配置模型窗口，有当前折叠引用 | `<context-folding scope=64hex />`，会话内保持稳定。 |
| 显式配置已知模型窗口 | `<context-budget used_estimate=N capacity=N output_reserved=N available_estimate=N basis=json-utf8-bytes/4 scope=64hex />`；无当前折叠引用时省略 scope。 |

`64hex` 是占位说明，实际值为完整 64 位十六进制 scope。使用量为 `ceil(JSON UTF-8 bytes / 4)`，包括提示自身，已知容量和输出预留用于计算剩余量，不根据模型名称猜容量。已有的本插件提示更新而非堆积。显式启用预算后，无折叠请求也有预算提示开销；常驻工具定义的开销也不会因为动态提示省略而消失。

预算不会触发选材、强制折叠、删除旧记录或调用模型生成摘要。Agent 不输出标记，系统就不主动收起内容。

## 可验证的合同

`status` 默认只返回数量、最近决策及累计净减少估算，`detail:true` 才包含完整统计。`decision.netTokensEstimated` 是最近一次请求的净减少估算，`cumulativeNetTokensEstimated` 是成功请求累计估算，二者不是同一指标。状态查询不会解除折叠。

实现应覆盖以下行为：配对与未闭合、损坏区域局部保留、嵌套子区不折叠、跨 Assistant 消息、用户边界、工具结构完整、延迟与重试、新出现的同内容、哈希变化、前缀冲突、完整恢复、只读分页与显式保护、存档失败回退、短批次收益拒绝、成熟批次再检查、默认空闲不追加提示，以及两种提示不累积。

这些是协议要求，不是测试完成声明。实际运行回执与宿主验证应分别记录，不把本地请求投影测试写成真实会话、默认 compaction 或账单节省已经验证。
