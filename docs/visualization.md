# 本地查看折叠统计

报告读取本机保存的统计与归档元数据，生成离线 HTML。它不是在线监控，也不测量模型质量、宿主 compaction 时机或真实账单。

```sh
bun src/cli.ts report --output /absolute/path/folding-effects.html
```

输出必须是不存在的绝对路径，父目录已经存在。使用自定义状态目录时，在相同环境中运行：

```sh
MAGPIE_CONTEXT_FOLDING_STATE_DIR=/absolute/state/directory \
  bun src/cli.ts report --output /absolute/path/folding-effects-2.html
```

可加 `--scope S` 查看一个会话。scope 是恢复能力值，避免写入文件名或分享给其他会话；报告使用临时匿名会话编号。

当前注释协议的记录会显示完整请求输入与返回投影的前后字节数、token 估算、本次替换段数、已有引用数、等待数及响应核实状态。每个会话只显示最近已记录的请求；宽限期、失败和未核实响应不会冒充成功折叠。缺少这些字段的旧归档明确显示“未记录”。

需要持续在客户端查看时，可使用 `statusline`、`sessions` 和 `hook` 命令；Claude Code 状态行与 Codex 通知的接入配置见 [客户端显示接入](client-visibility.md)。

## 统计口径

当前快照数量与全局累计数量不同。清理归档后，全局计数仍可能保留。估算 token 减少使用请求 JSON 的 UTF-8 字节数除以四，不能当作 tokenizer 实测。数据库大小是本地存储占用，不是请求大小。

旧数据库中的历史层、旧式分组折叠、费用证书和策略拒绝原因仍可能显示。这些属于旧实现的记录，不能解释成 0.4.0 继续使用三档、阈值或成本门槛。未记录的指标保持未知；历史证据不会因升级而成为新协议的验证结果。

0.4.0 是否折叠应根据标记配对、请求延迟、恢复入口、归档提交和最终视图判断。不要根据旧报告中的 `below-threshold` 等历史原因重新添加已经移除的配置。当前配置与行为见 [README](../README.md) 和 [协议](annotation-protocol.md)。

## 读取与文件边界

报告仅读取现有统计和元数据，不读取正文，不改变折叠状态或恢复次数。没有状态时生成空报告，不用模拟值填充。生成文件不使用外部网络资源，原文、摘要、源文件路径和 scope 不写入 HTML。

文件以 0600 权限独占创建；重新导出使用新的文件名。报告是生成时的快照，没有逐次请求轨迹，不能绘制不存在的历史趋势。并发活动可能使分别读取的统计与元数据略有差异。
